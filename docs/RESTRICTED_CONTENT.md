# 受限内容(成人向等分级内容)的资源管理 —— 设计记录(2026-10-22)与实现状态(见文末)

用户要求(2026-10-22):NSFW 类资源**如何加密或遮掩、如何管理与配置**,纳入后续规划。
范围只在**资源管理**:隔离、加密、遮掩、访问、导出、审计。**不包含**露骨提示词、镜头/动作设计、此类 LoRA 的训练参数——
这与用户在 Obsidian《成人向与分集内容创作_技术选型与合规边界》里定的边界一致(可做:工作流、存储、批量、文件组织、AIGC 标识与元数据;不做:写露骨提示词、设计镜头动作、调 NSFW LoRA 参数)。
该笔记的三条硬红线(未成年人、真人非自愿、淫秽牟利传播)在系统里做成**可配置但默认开启、关不掉其中两条的闸门**(见"硬闸门")。

## 目标与非目标
- 目标:受限资源(模型/LoRA、素材、项目、成片)**默认看不见、不外泄、不明文落盘(可选)、可审计**;打开它要明确的动作;不影响普通项目。
- 非目标:不是内容审核或过滤系统(本地模型无运行时过滤,这里管的是"存放与可见性");不绕过任何平台规则;不自动分发。
- 诚实说明:本机 API 目前**没有登录鉴权**(路线图里有)。在鉴权做好之前,"解锁"只是**本机防误看/防误传的保险**,不是对本机其他用户的安全边界;真正的保密靠加密卷/加密存储。文档与界面都会这样写。

## 一、分级(rating)——配置驱动,不写死
`config/defaults/content.toml`(用户目录可覆盖):
```toml
[content]
default_rating = "general"
vault_root = ""                 # 受限素材的根目录;空 = $STORY_AGENT_HOME/vault。可指向加密卷(如已挂载的加密磁盘映像)
encryption = "volume"           # off | volume(依赖加密卷,系统只检查是否挂载) | app(应用层逐文件加密)
key_source = "keychain"         # app 模式的主密钥来源:keychain | env | prompt
unlock_ttl_sec = 900            # 解锁后多久自动重新上锁
[content.ratings.general]
[content.ratings.restricted]
label_key = "content.rating.restricted"
mask_ui = true                  # 界面默认遮掩(模糊缩略图,不显示文件名/提示词摘要)
vault = true                    # 存入 vault_root,不放在 projects/…/media
log_prompts = false             # 提示词不写日志与 LLM 记录
allow_export = false            # 默认不进交付包/素材包/剪辑往返;导出需显式勾选并确认
allow_remote = false            # 不送云端模型(忽略项目的 allow_remote)
```
分级可增加(例如再分"暴力""成人"各自策略);每个级别的行为都是配置,代码只读策略。

## 二、哪些东西带分级
| 对象 | 怎么带 | 继承 |
|---|---|---|
| 项目 | `projects.rating`(立项时选,类型/方案可声明默认级别) | 其下作业、素材、规格、产物都继承 |
| 模型/LoRA | `models.toml` 里 `rating = "restricted"`(这类权重放在 vault 或加密卷;默认选择器里不出现) | 用了受限模型的作业,**产物自动标为受限**(不依赖人记得) |
| 素材 | `media_assets.rating`(继承项目/模型的较高者) | 导出、预览、日志都按它走 |
| 素材库条目 | `library_items.rating` | 同上 |
| 管线方案 | 方案可带 `rating`;受限方案由用户自建(程序自带的方案不含此类模型) | 项目选了它即受限 |

## 三、存放与加密
1. **隔离存放**:受限素材写入 `vault_root`(与 `projects/…/media` 分开);账本只记相对路径 + `rating`。
2. **两种加密方式(配置选)**
   - `volume`(推荐,macOS):`vault_root` 放在用户自己建的加密磁盘映像/加密卷上;系统**只检查它是否挂载**,不替用户挂载或卸载(与"系统只启动用户列出的东西、从不停止别人"的规则一致)。卷没挂载 → 受限素材显示"已锁定",相关作业排队并说明原因。
   - `app`:应用层逐文件 AES-256-GCM,每文件随机密钥,由主密钥包裹;主密钥来自 macOS 钥匙串(默认)/环境变量/启动时输入。文件在"ffprobe 校验通过"之后才封存(`seal`),读取时流式解密给播放器。
3. **作业怎么读受限输入**:worker 为作业建一次性工作目录(明文只存在于其中),作业结束即删除;失败也删。`app` 模式下这是唯一出现明文的时刻,文档写明。
4. **回收站与删除**:放回收站仍是加密的;**永久删除由用户在界面里明确触发**(`app` 模式即销毁该文件密钥,等同安全擦除);系统自己不自动永久删。

## 四、遮掩与访问
- 受限素材在列表、看板、预览里**只给遮掩图**(封存时一并生成的低分辨率模糊缩略图,单独存放),不显示文件名与提示词摘要。
- **解锁会话**:界面上"查看受限内容"→ 输入/确认 → 限时会话(`unlock_ttl_sec`)内才能取原文件和播放;会话到期自动重新上锁;每次解锁/查看/导出写**审计记录**(谁、何时、哪个对象)。
- API:`GET /assets/{id}/file` 对未解锁的受限素材返回 403(错误码 `content.locked`,带 remediation);SSE、作业列表、`/api/meta` 不含受限素材的路径与缩略图。
- 日志与 LLM 记录:`log_prompts=false` 的级别,提示词在日志和 `llm_transcripts` 里存摘要哈希而不是原文。

## 五、导出与外发
- 默认:**交付包、素材包、FCPXML 往返包都排除受限素材**;要包含,必须显式选择并确认"对象已满足年龄与同意要求",确认记入审计与包内清单。
- 云端模型:受限作业一律不送云端(项目的 `allow_remote` 对它无效)。
- AIGC 显式/隐式标识与来源记录**照常强制**(合规不因分级而关)。

## 六、硬闸门(不是普通开关)
来自用户笔记的三条红线,做成启动作业前的检查(配置可加严,**不可关闭前两条**):
1. **未成年人**:受限项目里每个角色必须有明确的成年年龄(≥18)声明;缺失或为未成年 → 拒绝生成并给出原因。外貌描述里出现未成年指向的词,按词表(配置)拦截并提示。
2. **真人非自愿**:使用真人参考图/声线/LoRA 的受限作业,必须有已记录的本人同意(沿用现有 `require_likeness_consent`、`require_voice_consent`,受限级别下不可关闭)。
3. **牟利传播**:不做分发功能;导出包里写明"仅限自用"提示(文案走 i18n),不对接任何分发渠道。

## 七、模型与资源管理(配置与体检)
- `models.toml` 里受限模型带 `rating` 与 `license_tag`;体检按"受限"分组显示,**默认不出现在模型选择器**,解锁后才可见。
- 下载队列、权重目录、LoRA 目录的位置写在配置里;系统只读与校验(sha256),不替用户下载。
- 备份:`db migrate` 的快照包含受限素材的账本,但不含 vault 文件本身;vault 的备份由用户对加密卷自行做(文档写明)。

**已做**:`content.toml`(分级策略;任何用保险库的分级必须保持 `gates = true`,`min_adult_age` 不得低于 18);迁移 017(`projects/media_assets/library_items.rating`、`characters.adult_confirmed`、`content_unlocks`);`storyagent/content.py`(分级继承 `max(项目, 模型)`、硬闸门、保险库可用性、解锁会话、导出检查、遮掩缩略图);保险库 `$STORY_AGENT_HOME/vault/`(worker 产物、上传、素材包导入、剪辑回导、素材库副本都按分级落盘);API 遮掩(`AssetOut/JobOut/SpecOut/ProjectCard` 在锁定时清空路径/提示词/来源,文件接口 403 `content_locked`,`/mask` 模糊缩略图);解锁/上锁/查看/导出/成年声明写审计;交付包、素材包、FCP 包、平台交付默认拒绝并需 `confirm_restricted`;模型调用日志只留摘要;CLI 与网页(立项选分级、项目页解锁条与徽标、遮掩磁贴、角色"已确认成年"、导出确认勾选)。
**与设计的差别**(都是有意的取舍,写在这里以免误以为已覆盖):
- 加密只做 `volume`(靠用户自己挂载的加密卷,`volume_mount` 检查是否挂载)。`app` 逐文件 AES-GCM 没做:需要加密依赖(`cryptography`),装依赖和密钥来源(钥匙串)需要你拍板。
- 保险库卷未挂载时,受限作业**直接失败**(`failed_validation` / `vault_unavailable`,挂载后在队列里重试),而不是"排队等待"。
- 遮掩范围:素材、作业输入、规格提示词、项目卡片、模型调用日志。**不遮**:剧本/对白/分镜文字(故事库)、作业事件流里的进度文字、体检页;受限模型用在普通项目里时,其作业输入仍是可见的(产物本身会被标为受限并进保险库)。
- 作业表与素材来源里的提示词仍在数据库里(未加密);`log_prompts = false` 只管模型调用日志。需要保密的数据库请放在加密卷上。
- 分级只能在项目还没有文件时更改(不做文件迁移)。
- 模型选择器里隐藏受限模型、体检按"受限"分组:没做。
- 词表只拦截提示词和角色文字,不是内容审核;"真人非自愿"靠既有的声线/肖像同意记录,系统无法核实真实性。

**管线方案的分级(2026-10-22)**:`pipelines.toml` 的方案可带 `rating = "restricted"`:用它新建的项目至少是该级别(不能被调低),把普通项目切到它也升级(已有素材时拒绝,和改分级一样)。受限模型 + 受限方案的示例(Lustify 经 Draw Things)见 `docs/PIPELINES.md` 末节与 `docs/examples/drawthings-lustify/`。仍是纯管线接线:不含提示词与镜头设计。
