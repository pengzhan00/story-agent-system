# Workflow: story, media, episode

One sentence in, an editable production out: characters, locations, script, shots, music/theme/sfx and — for every one of them — a **generation spec** (prompt, parameters, seed, references) that a person can edit and regenerate. The workflow writes the story and drafts the specs; the media layer (`docs/MEDIA_CONTRACT.md`) turns specs into pictures, voices, music and video.

```
analyze → cast → (outline) → script → scenes → music → shotplan → specs → produce → compose
└────────────── story (default run) ───────────────────┘  └─ media ─┘ └ episode ┘
```

A plain resume runs the seven story stages only; `produce` and `compose` are started on purpose (Web buttons "生成素材" / "合成成片", or `--stage produce`), or by a **full run** ("一键做完整部", `workflow run --full`, `params.full`): see "One run to the film" below. A resume (plain or full) also redoes the stages that a stage it runs makes stale: a project whose locations are stale gets its shot plan and specs redone in the same run, not from the old ones.

| Stage | What it does | Agents (LLM roles) |
|---|---|---|
| `analyze` | premise → production plan (genre, tone, acts, cast and place lists) and visual style | `director.analyze`, `art.style` |
| `cast` | one design per character (look, voice profile, image prompt, voice sample text) | `character.design` |
| `outline` | season: one request plans every episode (title, synopsis, opening hook, cliffhanger); optional, part of a plain resume only when the season plans more than one episode; the script stage then follows the episode's entry | `screenwriter.season` |
| `script` | outline of acts and scenes, then a shot breakdown per scene; or `source_text` adapted into the same structure | `screenwriter.outline` / `screenwriter.adapt`, `screenwriter.shots` |
| `scenes` | one design per location | `scene.design` |
| `music` | background cues, a theme song with lyrics, sound-effect list | `composer.bgm`, `composer.theme`, `sound.design` |
| `shotplan` | deterministic: builds every shot's `shot.v3` render payload (timing from dialogue, camera, subject, style) | – |
| `specs` | deterministic (+ optional `shot.visual` per shot): seeds the editable specs, with dependencies | `shot.visual` |

| `produce` | submits a media job for every spec that has no up-to-date asset, in dependency order: (1) portraits, scene keyframes, music, theme song, sound cues, dialogue voices → (2) shot keyframes → (3) shot videos (from the keyframe). Skips what is current; reports what it had to skip (`no_voice`, `no_model`, `no_keyframe`); jobs that fail fail the stage but the rest is kept | media adapters via the ledger/worker |
| `compose` | builds the timeline (speech first, see below), renders `episode.mp4` + `episode.srt` with ffmpeg, then runs QC | `compose.assemble` adapter |

Agents are **data**: `storyagent/agents/specs/*.toml` (+ `schemas/*.json`). Copy one into `$STORY_AGENT_HOME/config/agents/` to change a prompt or model role without touching code. Each agent runs on an LLM *role* routed by `llm.toml` to a backend (ollama / llamacpp / openai_compat); output is requested as schema-constrained JSON, repaired if needed, validated and re-asked up to `max_attempts` times.

## Story coherence

A film is only as coherent as its outline, and nothing read the outline before. Dramas made without these checks had a villain who was designed and never on screen, a parcel whose sender was never told, a woman who was "just there" at the beach and a line said one shot before it was true. The `script` stage now does four things (`workflow/coherence.py`, `workflow/stages.py`):

1. **The outline states what is true.** `screenwriter.outline` fills `facts` (5-12 plain sentences: what happened before, who did what and why, every secret with its answer, what each person wants, how it ends) before any scene, and `threads` after the scenes (each thing planted, the scene that plants it and the later scene that pays it off). Both are kept in the project's workflow data under `story:<episode>`.
2. **The outline is read before a shot is written.** Plain code (`outline_problems`) finds a person of the cast who is in no scene (a single piece; an episode of a series need not use everyone), a person in a scene who is not in the cast, a scene without a beat, and a thread with no pay-off scene or one paid off before it is planted. The `reviewer.outline` agent reads it for cause, things planted and dropped, why people are where they are and what they know, time and place, contradictions of the facts, and the end. Serious (`high`) problems send the outline back to the writer with the notes and the outline they are about (`feedback`, `current`), at most `[workflow] outline_review_rounds` times (default 2). Of all the versions the one with the fewest serious problems is kept (then the best score), so a rewrite that made things worse is thrown away. An adaptation of a source text is read and reported, never rewritten.
3. **Every scene is written knowing the story.** `screenwriter.shots` is given the story so far scene by scene (`story_so_far`: place, time, who, what happened; all scenes, the oldest shortened first), the last lines spoken before the scene (`last_lines`) and the `facts`, with the rule that nothing in the scene contradicts them, nobody knows what they were not shown or told, and nothing is explained twice. Before, the writer of scene 7 knew one sentence about scene 6.
4. **The script is read once more.** After the shots are written and before the shot cards, `reviewer.logic` reads the script in order like a viewer: lines against the facts or earlier scenes, a secret said too early, the same thing told twice, a beat the shots never show, a line a shot too early. Scenes with a serious problem are written again with the reader's notes and the shots they have (at most `script_review_max_scenes` per round, `script_review_rounds` rounds, default 4 and 1), then read again.

A later episode is told how each earlier one ended (its last scene) and the facts fixed so far, not only the synopses. What the checks found and did is the `story_check` of the script stage summary (and `story_check:<episode>` in the workflow data): per part the score, how often the text went back, the scenes written again and what is still open; the Web "工作流" page shows it under "剧情自检". Run parameters: `story_check=false` skips both checks, `story_check=true` reads an existing script again (a plain resume with nothing to write reads nothing), `outline_review_rounds` / `script_review_rounds` override the configuration. A revision a person asked for (`feedback`) is not second-guessed by the reader. The checks cost language-model time only (a few requests per episode); they are judged by a model, so they lower the odds of a hole, they do not prove there is none: read "剧情自检" before spending hours on pictures.

## Readiness: every run is looked at before it starts

`workflow/preflight.py`, `GET /api/projects/{id}/preflight`. The same look for a run to the film (`params.full`) and a run of single stages (`stages`): it covers exactly the stages the run will do. A `block` finding refuses the run (409 `not_ready`, the findings in `detail`); a `warn` is shown and the run goes on. `params.skip_preflight` starts it anyway, `[workflow] preflight = false` switches the refusal off. The worker looks again right before the first media job (`workflow.not_ready`), which also covers runs started from the command line.

What can keep a run from its film, each kind of thing looked at in one place:

| What is missing | Looked at by | Findings |
|---|---|---|
| Someone to write (story stages) | `check_llm`: every role the stages use, its backend, its model | `llm_role`, `llm_down`, `llm_model_missing` |
| Something to make with | `check_media`: a model for the kind, its adapter, its service, its tool and weights | `no_model`, `no_adapter`, `service_down`, `not_installed`, `degraded` |
| Leave to make it | the content gates of the project's rating | `gate` |
| Inputs that fit the model | `check_references`: the reference images each picture carries against what its model states it takes (`media/refs.py`); known from the uploaded pictures before the story has specs | `too_many_refs` (refused outright: blocks), `refs_dropped` (only the first are read: told); `values.models` = the models of the same kind that take that many, `_only` when there is none; `detail` = the people concerned |
| | `check_jobs`: every job the run can build now is shown to the worker's own gate (`media/gate.py`: references, compliance, content, prompt language, parameters, the adapter's `validate`) without being queued, one job per shape (model, what it is for, number of references) | `refused` with the reason the worker would give (`values.what`, `values.count`, `values.error`); a sound effect or music job only warns |
| Voices | `check_voices` | `voices_auto`, `voice_shared`, `no_voice` |
| Someone to run it | `check_worker`: a scheduling worker leaves a sign every 10 s (`<home>/run/worker.json`, `media/worker.py`); the API reads its age before a run is queued | `no_worker` (told, not refused: the run waits in the queue until a worker is started) |

Every way work starts meets the same checks:

| Started as | Before it is queued | In the worker |
|---|---|---|
| a run to the film (Web "一键做完整部", `params.full`) | API look ahead, 409 `not_ready` | look again before the first media job |
| a run of single stages (Web stage buttons, the production plan, `stages`) | the same API look ahead for those stages | the same |
| `storyagent workflow run` | none (it queues directly) | the same |
| one job (workshop, a spec made again, `media submit`, a retry) | none | `media/gate.py` on that job: it fails at once with the reason |

**Reference images** are stated once per model: `Adapter.reference_rule(kind)` (`ReferenceRule(most, used)`: more than `most` is refused, only `used` are read) or, for a model whose adapter cannot know (a ComfyUI workflow, a `cli` / `http` connector), `max_refs` / `used_refs` in its models.toml entry. Draw Things takes 1, H3-Image 16, mflux reads the first when it generates and all when it edits. A model that states nothing is never reported and never offered as one that takes several (`tests/test_readiness.py` keeps the list of adapters that leave it to the model entry).

## One run to the film

`params.full` on a resume (`POST .../workflow/runs {"params": {"full": true}}`, CLI `storyagent workflow run --project N --full`, Web "一键做完整部") runs every stage that is not done from where the project stands to the film: the story stages, `produce`, `compose`; with `episodes` / `season`, each episode in turn from its story to its film. It needs the worker.

* **Looked at before it starts**: see "Readiness" below. A picture service that is not running, or a model that cannot take the reference images it would be given, costs one message, not one failed job per shot after the story was written.
* **Voices**: people without a voice get a library voice by gender, one each (`voices.auto_assign`, consent-flagged voices only), and it is put on their lines; the produce summary lists `voices_given` / `voices_missing`. Someone the library has no voice for speaks with the speech model's automatic voice when it has one (`media/tts.py`; the look ahead says `voice_shared`: everyone sounds alike), else the line is skipped as `no_voice`. Also on its own with `params.auto_voices`.
* **A few failed assets do not stop the film.** In a full run (`keep_going`, on with `full`) a `produce` that ends with failed jobs is marked failed and keeps its summary (which assets, why), and `compose` still cuts the episode from what exists and reports the rest as warnings; the next full run makes only what failed and cuts again. When nothing at all could be made (and nothing was there to reuse) no film is cut from nothing: the run fails at `produce`. A story stage that fails still stops the run (the next episode is written from this one); an episode whose film could not be cut does not stop the episodes after it, and the run ends failed.
* Without `full` nothing changed: a failed job fails the run at `produce`. The summary of a failed stage is now kept in both cases.

## Rules that matter

* **Resumable.** Every LLM result is saved as soon as it arrives (each scene breakdown, each character). A run that fails or is cancelled keeps everything done so far; running again only produces what is missing.
* **Stale propagation.** Completing a stage marks the stages that depend on it `stale` (`DOWNSTREAM`); a resume run redoes stale and pending stages. Explicitly re-running `analyze` re-plans by design; `force=true` redoes stages whose output exists.
* **Never overwrite people.** Specs seeded by the workflow have `author='agent'`. A spec a person edited (`author='user'`) or locked is never touched on re-seeding; agent drafts follow the story (new version). Locked shots survive `shotplan`; every other shot is rebuilt **in place**, so its id — and the specs and assets attached to it — stay.
* **Unknown speakers.** A dialogue line whose speaker matches no character is reported (`unresolved_speakers`) and shown with `character_id: null`; reassign it or add the character.
* **Set pieces get more shots.** The outline gives each scene a `scene_type` and a `shot_count` (a fight, an intimate scene or the climax is a chain of moves, 2–3 times the usual); the `script` stage breaks the scene into that many shots, kept between 1 and `shot_count_factor` (default 6) × `shots_per_scene`. A fresh scene's shots are cleaned: a narration repeated from an earlier shot or from the scene is dropped, a text field that is JSON written out as text is flattened.
* **Shot cards and fixed descriptions** (`workflow/detail.py`). A set piece is written in two passes: the writer role (`screenwriter.shots`) writes each shot as a summary; then, at the end of the `script` stage, the prompter role (`shot.detail`, routed in `llm.toml`, so a different model can do it) turns each shot of a scene whose `scene_type` is in `[workflow] detail_scene_types` (default intimate, action) into a *card*: per person the clothing zone by zone, the body parts in view and their form, pose, where every limb is and whose it is, face and skin; the contact; the one movement with rhythm and small motions; the camera (size, angle, lens, crop, focus); light, setting with a scale cue, sound; the opening and closing still; the motion only; and the state of clothes and marks at the end (the next card's ledger). A card is linted (empty fields, words that show nothing such as `detail_vague`, an opening still under `detail_min_words`, the same position three shots running, an object such as a knife that no sentence of the `image_prompt` says anyone holds: `detail_held_things` / `detail_holder_words`) and asked again up to `detail_attempts` times with the problems named; one that still has problems is kept with them listed. The writer is given the look each person wears at that point of the story (`wardrobe`, from `character_looks`) and must name the same garments in the same colours in every card of the scene (a change only through the ledger), say how many people are in frame in the first sentence of `image_prompt`, and give every used object a visible holder; these came from a drama whose keyframes showed a third person, a floating knife and outfits that changed colour from shot to shot. The card lands in the shot's `render_payload.detail`, and the keyframe prompt is the card's `image_prompt` (one plain paragraph: who does what in which position, one sentence of contact, then hands, faces, place, light and viewpoint; a card without one builds it from the pieces) and the video prompt is built from the card (no second guess by `shot.visual`): the opening still, the card's one main movement (`motion.main`, linted: no chained actions, at most `detail_main_max_words`), rhythm, small motions and camera, and no ending pose. A clip starts from its own keyframe only: it does not end on the next shot's keyframe unless `[workflow] video_chain_end` is on or the shot names its `end_shot_id` (a clip told where to end cuts or dissolves into it half way, with ghosting and changed clothes; measured on shot 454: with the next shot's still as last frame the clip jumped to it in the last frames even at 2 s, without it the picture stayed steady for 5 s). A card from before the plain `image_prompt` paragraph existed (it has no faces, expressions or clothes to put in the keyframe prompt) is written again by the script stage on any plain run, and until then the `produce` stage skips that shot's keyframe and clip with the reason `old_card` instead of drawing it from nothing; `redetail_shots=["3.3.4"]` (act.scene.shot) rewrites just the named cards. Chinese never reaches a picture or video model: a card with Chinese words in a prompt field (`image_prompt`, `start_frame`, `video_motion`, `motion.*` ...; a person's name is not one) is sent back to the writer like any other lint problem, and the worker refuses an `image.generate`, `image.edit` or `video.generate` job whose prompt still holds Chinese for an English-only model (`invalid_input`, the words named; sound clips may carry a spoken line and are only warned). Keyframes are routed by scene: a plan (or `[workflow]`) that names `sfw_image_model` sends the shots of every scene whose `scene_type` is not in `adult_scene_types` (default intimate) to that model, written on the keyframe spec's `model_ref` (a user-edited or locked spec is kept; assets made by the other model then show as outdated), because an adult checkpoint draws people undressed in any scene. When the movement is the shot (fight, sex, running) the writer must state its size and pace (the body travels a clear distance, long steady strokes); "slightly/gently" are for quiet shots only, because a video model barely moves for them. A clip that carries its own sound (project option `video_with_sound`) is made by the project's `video.av` model: the plan's, or the one picked in the pipeline panel (e.g. `minimax-h3`, which reads the first frame only, makes room sound but speaks no lines); with no pick it is `ltx-2.5-av`. What never changes is written once per person and place by `anchor.fixed` (`anchor:character:<name>`, `anchor:location:<name>` in the project's workflow data, locked and editable there) and pasted into every shot prompt of that person or place, so build, skin, marks, the size of the bed and the layout of the room are the same in every picture. Run parameters: `detail=false` skips the pass, `redetail=true` writes all cards again (`redetail=problems`: only those with problems or without an `image_prompt`), `redetail_scenes=["3.3"]` (act.scene) just the cards of those scenes, `reanchor=true` (with `redetail`) the fixed descriptions too. Shots written again by a revision carry no card, so the next run writes theirs.
* **The review reads the whole package.** `review` runs the story editor (`reviewer.script`) and, when cards exist, a continuity supervisor (`reviewer.continuity`: clothing, marks, props, light, positions against the fixed descriptions), a producer of the pictures (`reviewer.producible`: can each card be drawn and animated, limb ownership, one action in five seconds) and, for a project whose rating is not `general`, a content director (`reviewer.rating`: intensity against what the rating asks, repeats, the adult-only limits). The scores are averaged, each issue names its lens.
* **One active run per project**, executed by the worker (`storyagent worker`) or inline (`storyagent workflow run --inline`).

## Progress you can see

A run publishes `progress` (see `docs/API.md`): overall percent, per-stage bars, items done/total, the current message, elapsed time and ETA. Stage weights (`workflow/progress.py: STAGE_WEIGHTS`) only shape the overall bar; inside a stage the bar is exact. The terminal shows the same data:

```

```

## Commands

```bash
storyagent llm check                                   # is every role's model installed?
storyagent workflow run --project 1 [--stage script] [--param episode=2] [--param source_text="..."] [--force]
storyagent workflow run --project 1 --inline           # no worker needed; draws the progress bar
storyagent workflow status --project 1                 # stage states (+ per-stage bars of the active run)
storyagent workflow watch [RUN_ID] [--project 1]       # follow a queued/running run
```

Params: `premise`, `acts`, `episode`, `source_text`, `visual_prompts` (false = deterministic prompts, no extra LLM call per shot), `min_shot_sec`, `max_shot_sec` (default: the project kind's `shot_sec`, see [WRITING.md](WRITING.md)), `force`.

The writing agents (`screenwriter.*`, `reviewer.script`, `workshop.story|script`) are not tuned to one kind of work: the form of the work (`kinds.toml` `writing`), the genre notes (`genres.toml`), the picture frame, the longest spoken line and the shot length reach them as the variables `form_guidance`, `genre_guidance`, `frame_note`, `dialogue_chars`, `shot_sec`.

**Revising with feedback**: `--stage script --param feedback="..."` (optionally `revise_scenes=["1.3","2.1"]`, as `act.scene`) keeps the outline and writes again the shots of the named scenes (every scene when none is named) from the feedback and their current shots (`screenwriter.shots` inputs `feedback`, `current`). The Web "工作流" page offers it under the script review: tick the review issues to apply, add own notes; from the page the rewrite is a proposal (`propose=true`), see below.

**A rewrite is read before it reaches the script** (`workflow/revisions.py`, Web "修订预览"). Every rewrite of a written scene is kept with the shots it replaces (`workflow_data` key `revisions:<episode>`, the last 60):

| Where the rewrite comes from | What happens to it |
|---|---|
| a revision asked for on the page (`feedback` + `propose=true`; `revision_source` = `review` / `own`) | `pending`: the script, its stage and the stages built on it stay as they are (the stage summary says `proposed`, `kept`) |
| the logic reader of the script stage, run of single stages (`[workflow] script_review_apply = "confirm"`, the default) | `pending`; the script is not read a second time; `story_check.script.proposed` names the scenes |
| the logic reader in a run to the film (`full`), or `review_apply=auto` / `script_review_apply = "auto"` | `applied` at once, so the run is not stopped for a person; what it replaced is kept and can be taken back |
| `feedback` without `propose` (the command line) | written straight into the script, as before |

`GET /api/projects/{id}/revisions?episode=` lists them with both sides as plain text; `POST .../revisions/decide {episode, accept, discard, revert}` puts confirmed ones into the script, drops them, or takes an applied one back. A scene that no longer reads as it did when the rewrite was written (somebody edited it) is never overwritten: the proposal is discarded and reported in `conflicts`. After a change the `script` stage is `stale`, so the next resume writes the shot cards of the changed scenes and does the later stages again (media: only what the change affects). Nothing is decided while a run of the project is active (409).

## Produce and compose

* `produce` params: `tier` (draft/preview/final; default `[workflow] tier`), `skip` (list of spec subject types, e.g. `["shot.video"]`), `force`, `takes`. Dialogue needs the character's `voice_ref_audio` (upload a sample in the Web "故事" page) or `[workflow] default_voice` in `services.toml`.
* `compose` params: `episode`, `burn_subtitles`, `edit` (overrides `[edit]`), and `shots` (a list of shot ids): only those shots are cut, in story order, e.g. a preview of one scene (`--param 'shots=[496,497]'`). Pair it with `produce --param only=[...]` so only that part is made.
* `compose` timeline (`compose/timeline.py`, pure and tested): the dialogue is generated first and measured with ffprobe; a shot lasts `max(planned, lead-in + lines + gaps + tail)`. A clip that is too short is slowed down (up to `max_slowdown`) then holds its last frame; one that is too long is trimmed; a still image gets a slow push-in; a shot with no picture becomes a black card. Every improvisation is a **warning** in the report (`no_picture`, `no_video`, `missing_speech`, `no_bgm`) - the episode still renders.
* Audio: music bed ducked under the voices (sidechain), loudness normalised to `[mix] loudnorm_i` (-16 LUFS), skipped when there is nothing audible.
* **AIGC marking** follows `compliance.toml` / project settings: `implicit_metadata` writes a `comment` tag into the container; `explicit_label = overlay` burns a small label (top-left, text from the catalog key `compliance.label.aigc` in the project's content language) over the whole film; `both` adds a two-second end card. A label needs an ffmpeg with libass (`ffmpeg-full`): without it the job is refused with `missing_tool` rather than delivered unlabelled.
* **Sound and edit grammar** (`compose/timeline.py` builds it, `media/runners/assemble_episode.py` renders it; every knob is in `delivery.toml`, plans may override `[edit]`/`[mix]`):
  * *Room tone* (`[mix] room_tone`, `room_tone_db` -50, `room_tone_color`): a faint noise bed, one block per run of shots of a scene, faded at both ends, so a pause between lines is room and not digital silence. It is never loudness-normalised on its own.
  * *Music cues*: the music stage writes one bed per mood, each tagged with the scene it was written for (`scene_ref`). The timeline plays them in story order, each from its scene until the next, cross-faded (`music_crossfade_sec`); a single bed is still one bed from the start. A bed whose scene is not in the episode is reported (`music_cue_scene_missing`).
  * *Scene mix*: where nobody speaks for `music_swell_min_sec` the music comes up `music_swell_db` (ramped); under speech it is ducked as before (sidechain).
  * *J-cut / L-cut* (`[edit] j_cut_sec`, `l_cut_sec`, default off; the tv and film plans use a 0.3 s J-cut): only inside one scene, the sound stays where it is and the picture cut moves, so the next line is heard before its picture (J) or the last line runs over the next picture (L). Neighbouring shots trade seconds, the total is unchanged, and a cut that would leave a shot under one second is skipped. The later segment carries `cut_in: "j"|"l"`.
  * *Cross-dissolve* (`[edit] dissolve_sec`, default off; the film plan uses 0.8 s): at a change of scene the shot before melts into the next (ffmpeg `xfade`). The shot before is rendered `dissolve_out` seconds longer and the two overlap, so the film is still exactly as long as the timeline. It wins over `scene_fade_sec`. Without the `xfade` filter the cut stays hard and the report says `dissolve_unavailable`.
* **QC** (`compose/qc.py`, `[qc]` in `delivery.toml`): file size, duration, resolution, aspect vs the delivery profile, audio track, mean volume, loudness (±3 LU around the target), black share, frozen picture. `episode_length` against the profile range is advisory (drafts are short). Two more advisory checks measure picture artifacts on a small grey copy of the film (`compose/artifacts.py`, plain Python on ffmpeg's raw frames, `[qc] artifacts = false` skips them): `flicker` (brightness swinging up and down frame to frame; a cut or a fade does not count) and `banding` (horizontal stripes inside a block of the frame). The metrics name the shots the windows fall in (`artifact_shots`). **Uncalibrated:** the limits (`flicker_amp`, `stripe_amp`, `stripe_ratio`, `max_*_sec`) are set above everything in the 11 pilot clips, so they flag only obvious cases (synthetic stripes and pumping are caught in the tests); tune them on your own footage. `storyagent qc artifacts FILE [--stripe-amp N ...]` checks one clip, e.g. a generated shot before it goes into the film. The result is in the compose stage summary and shown under the player.
* **Export**: `storyagent export episode --project N --out DIR` or `GET /api/projects/{id}/episodes/{n}/package` (zip): `episode.mp4`, `episode.srt`, `stems/` (music + each spoken line as used), `provenance.json` (per source asset: model, version, licence, attribution - no prompts, no paths), `manifest.json` (sha256 per file + QC). Rebuilt from the ledger, so it always describes what was rendered.

`produce` also takes `shots` (shot ids): it makes only what hangs on those shots (their keyframes, clips, dialogue, sound), alongside `only` (spec ids) and `skip`.

**A character's trained LoRA** (`characters.lora_ref`: a file path, or `asset:<id>` of a `train.lora` result): every keyframe spec of a shot she is in gets `params.loras = [{path, scale}]` (scale `[workflow] character_lora_scale`, default 1.0) and the trigger word the trainer recorded on the asset goes first in the prompt. The ComfyUI adapter copies the file into `[tools.comfy] loras_dir` with ComfyUI's key naming (`transformer.` -> `diffusion_model.`, header rewrite only; `media/lora_files.py`) and chains a `LoraLoaderModelOnly` after the template's own LoRA node, so the same job works on the official checkpoint and on an adult one. Measured (Krea 2 Raw LoRA, 30 images, 16 epochs): strength 1.0 holds the face on both; the clothes and backgrounds of the training set leak, so say the clothing in the prompt. Method and numbers: the Obsidian note `技能库/AIGC-图像/角色LoRA_训练与跨底座挂载方法`.
