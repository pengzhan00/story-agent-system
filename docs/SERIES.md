# 连续短剧(红果式)制作:设计与路线

终极目标:用本系统做出一部多集竖屏连续短剧(几十集,每集一到几分钟,每集有钩子和结尾悬念),而不是单个片段。
本文记录现状、缺口和分阶段做法。数值(集长、集数、画幅)**未经平台确认**,全部做成可配置的档位,不写死。

**目标时长不锁死**:从 10 秒广告、30 秒试播、90-180 秒连续剧单集,到微电影和 3 小时的大电影都可能。
`target_sec` 一个数决定写多少幕/场景/镜头、每个镜头计划多长、成片质检的时长窗口(目标 ±20%)。优先级:运行参数 > 项目设置 > 交付档位。
网页「工作流」页有「交付档位」和「目标时长」。当前限制:几十分钟以上的片,一次大纲请求写不下所有场景,需要分幕多轮生成(见阶段 2)。

## 现状(2026-10-21)

- 单集链路已通:创意 → 大纲 → 人物/场景 → 分镜 → 每镜头图/视频/配音 → 按"先量台词时长再排时间轴"成片 → 字幕/配乐/AIGC 标识/质检/交付包。
- 多集只是"命令参数 `episode=N`":第 N 集写剧本时只拿到前几集的梗概;阶段状态按项目(不是按集)记录,第 1 集跑完后第 2 集不会自动重跑任何阶段。
- 工坊(独立模块)只产出短片段;已补"成片"模块,可手工把镜头拼成一集。
- 算力:本机视频生成很慢(LongCat 一条 4 秒左右的片在 40 分钟以上仍未出结果,实测中),一部几十集不可能每个镜头都生成视频。

## 缺口

| # | 缺口 | 说明 |
|---|------|------|
| S1 | 全剧圣经 | 人物(外貌/声线/LoRA/参考图)、场景、画风、基调跨集锁定,每集只增不改 |
| S2 | 分集大纲 | 先写全季:每集标题、梗概、开场钩子、结尾悬念/付费点;写第 N 集时必须按它写 |
| S3 | 按集的状态与批量 | 阶段状态按 (项目, 集) 记录;"跑第 3-10 集"、"跑全部";逐集进度与总进度、ETA |
| S4 | 镜头分层与预算 | 每个镜头选 视频 / 静图+推拉 / 口型头像;按预算(GPU 小时)自动分配,关键镜头用视频 |
| S5 | 剪辑 | 转场/叠化、开场钩子、集末悬念卡、上集回顾、字幕样式、音效合成 |
| S6 | 连续短剧交付档位 | ✅ 已做:档位 `series_vertical_720`(默认 120 秒,范围 90-180,可改)+ 可调目标时长 |
| S7 | 跨集一致性 | 同一角色同一张脸:LoRA + 参考图在每集的镜头规格里自动带上 |
| S9 | ✅ 剧本→图→关键帧链路与生产计划 | 已做:关键帧以人物像/场景图为参考合成;生产计划列清单、确认后才生成;文字资产可一键建项目 |
| S8 | 系列看板 | 全剧每集每阶段的状态、已产出镜头数、耗时与剩余时间 |

## 分阶段

0. **试播集(先做,不写新框架)**:用现有项目工作流在真实模型上跑一集约 60-90 秒的成片,记下每类任务的实际耗时和画质。结果决定 S4 的分层策略。
1. **S6 + S3**:连续短剧交付档位;阶段状态加 `episode` 维度(迁移 007,`workflow_stages` 主键加 episode,老数据归第 1 集);`workflow run --episodes 1-10`。
2. **S1 + S2**:`series` 数据(圣经、分集大纲)与 `series.outline` 提示词;剧本阶段按分集大纲写;圣经锁定后各集只读。
3. **S4 + S7**:镜头分层策略和预算;LoRA/参考图自动带入镜头规格。
4. **S5**:转场、片头钩子、悬念卡、回顾;SFX。
5. **S8**:系列看板(Web)与批量导出。

每一阶段都要:有测试、i18n、文档,并按全局规则在"基线化"前跑 `software-system-review`。

## 多集改造设计(含 season;阶段 1-2 的落地方案,2026-10-21)

层级:**全剧(项目) → 季(season) → 集(episode)**。一部剧可以有多季(第一季 30 集,第二季换故事线),也可以只有一季。

读代码发现的事实(决定了方案):
- `workflow_stages` 主键是 (项目, 阶段),只有一份状态;剧本/分镜/规格阶段按 `params.episode` 工作,但状态不分集。
- 数据本身大多已分集:`scripts.episode_no`、`episodes`、`shots.episode_id`。**项目级**的有:`characters`、`scenes`(场景地点)、`music_themes`、`sound_effects`、`workflow_data`(`plan`、`style`)。
- 冲突点:`music_themes.scene_ref` 形如 `act01_scene02`,第 2 集会和第 1 集撞名;`music` 阶段按"已有 scene_ref 就跳过"判断,第 2 集的配乐会被当成已做。

**编号约定**:集保持**全剧连续的全局编号** `episodes.number`(作业、参数、素材槽位、文件名都用它,不用改一大片代码)。季是对集的分组:`episodes.season`(季号,默认 1)与 `episodes.number_in_season`(季内序号);对外显示 `S02E03`。
**季的内容**(新表 `seasons`:项目、季号、标题、梗概/主线弧、计划集数、目标时长 `target_sec` 覆盖、状态):季大纲(每集标题/梗概/钩子/悬念)属于季;**人物圣经**属于全剧但允许按季追加人物与"季内造型/状态"(例如第二季换装、时间跳跃);主题曲可全剧一首也可每季一首(`scene_ref="theme"` / `"s02_theme"`);交付档位与目标时长优先级:运行参数 > 集 > 季 > 项目 > 档位。

阶段的作用域:

| 作用域 | 阶段 | 说明 |
|---|---|---|
| 全剧(season=0, episode=0) | `analyze`、`cast` | 世界观、风格、人物共用(S1 圣经的雏形) |
| 每季(season=n, episode=0) | `outline`(新)| 写本季的分集大纲(S2),`script` 阶段按它写 |
| 每集(episode=n) | `script`、`scenes`、`music`、`shotplan`、`specs`、`produce`、`compose` | `scenes` 只补本集新出现的地点;`music` 的 scene_ref 加集号前缀 `ep02_act01_scene02` |

迁移 007:
1. 新表 `seasons`;每个项目补一行第 1 季;`episodes` 加 `season`(默认 1)、`number_in_season`(老数据 = number)。
2. `workflow_stages` 加 `season`、`episode`(默认 0),主键改 (project_id, stage, season, episode);老数据:`analyze/cast` 留 (0,0),其余阶段归第 1 季第 1 集。
3. `workflow_runs` 的 `params.episode` 保持,另加 `params.episodes`(列表)与 `params.season`,引擎按集顺序逐个跑每集阶段,进度按"集数 × 阶段"统一计。
4. (留到步骤 B 的迁移 008)`music_themes.scene_ref` 老数据补前缀 `ep01_`(主题曲不动)。
5. `DOWNSTREAM` 带作用域:全剧阶段重跑 → 所有季所有集的下游变 stale;某季大纲重跑 → 该季各集的 `script` 起变 stale;某集阶段重跑 → 只影响该集。

实现顺序(每步独立可测、可发布):
- A. ✅ 已做:迁移 007(`seasons`、`episodes.season/number_in_season`、阶段状态带季/集维度),`WorkflowState` 带作用域;`GET /workflow?episode=N`、`GET/PATCH /seasons`、`workflow run --param episode=N [--param season=M]`;网页暂时只看第 1 集。
- B. ✅ 已做:`music` 阶段按集(配乐 scene_ref 加集号前缀 `ep02_...`,主题曲全剧一首,迁移 008 把老数据归第 1 集),成片优先用本集的配乐;`scenes` 本来就只补缺的地点,`pending_stages` 按集。
- C. ✅ 已做:`params.episodes`("1-10"、"1,3" 或列表)与 `params.season`(该季已有的集,没有则按 `planned_episodes` 新建);全剧阶段只做一次,每集各自接着做(`params.resume`);进度条按"阶段 × 集"一条,总进度与 ETA 统一计;CLI `workflow run --project N --param episodes=1-10`;网页「制作流程」页有「第几集」和「批量」。
- D. 全剧圣经 + 季大纲(S1/S2):新增 `outline` 阶段(季级)。
- E. 系列看板(S8):按季折叠、每集每阶段状态、镜头数、耗时。
