## LTX-2.3 的关键限制

- 显式指定 `ltx_2.3_22b_distilled_1.1_i8x.ckpt`，8 steps、guidance 1.0。
- 每个请求显式传 `num_frames` 和 `fps`。帧数须为 8n+1（当前接入允许 9–361）；不要继承 app 保存的 5 fps。
- 返回帧数必须符合请求，否则任务失败；不会把单张预览图包装成视频。
- 参考图最多一张；API 对参考图尺寸有要求，使用时应与目标尺寸一致。多参考图走专门工作流。
- 文本编码器的 `.ckpt` 与 `.ckpt-tensordata` 是一套，不因索引头很小就判断为损坏。
- 这里只是 DT 的备用生成入口；Phosphene 的 2.3 训练 / IC-LoRA 与 2.5 生成不能混为同一能力。
- 当前配置许可字段只沿用登记值，不构成对底模或 LoRA 许可的重新核验。

## 不直接登记成“已可用”的组件

- MRT2：现有脚本在，但预期的独立运行环境缺失；先恢复环境再验收，不执行旧脚本中的 eval。
- InstantID、LTX-2.3 IC-LoRA：有组件不等于工作流跑通，保留待验。
- RIFE、H3 各变体：逐项核实运行时、权重及接口；旧笔记里的成功不代表当前提供者可调用。
- 缺少 fp8 scale 的 Krea2 ComfyUI 权重、`.partial` 下载：不能据文件名判为可用。

本轮无需为上述已具备权重的备选模型重复下载。mflux 保留但不作本机默认；不删除权重、硬链接或历史资产。
新增引擎可通过系统 connector / adapter 配置接入，但不是任意管线都能靠一个安装 API 自动可用；仍需运行时、
输入输出契约、取消与超时处理、资产登记和真实任务验证。
