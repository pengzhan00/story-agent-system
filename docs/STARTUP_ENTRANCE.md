# 后端停机时仍可用的网页入口

运行 `scripts/start.sh` 后，继续访问原 `http://localhost:8765`（或配置的端口）。轻量入口保留这个地址，
API 与 worker 使用私有端口；后端停止时显示“启动后端”，就绪后回到刚才的路径。

## 使用

- 系统 → 后端启动与退出：可点击“退出后端”，当前工作完成后退出，入口保持可用，可再次启动。
- 退出和登录启动设置需要应用管理员身份；未登录时先返回应用登录。普通启动只允许本机同源页面。
- 启动会运行 API 和 worker，因此数据库中的排队任务可能继续执行；不会自动提交新的素材任务或打开模型服务。
- 更新并重启保留原有排空协议。若取消正在等待的退出/重启，退出标记也会清除。

## 只设置一次的登录启动

在上述控制页点击“登录时保留启动入口”。它只写入当前用户的
`~/Library/LaunchAgents/com.storyagent.gateway.plist`，不打断当前服务；下次登录后，入口随登录启动，
后端仍由网页按钮启动。CLI 等价命令是：

```sh
.venv/bin/python -m storyagent.gateway --install-login
```

如果轻量入口本身也没有运行，浏览器无法凭空执行本机程序。首次采用需更新代码并重启现有服务一次，
再设置登录启动。开发时也可手工运行 `scripts/start.sh`；Ctrl-C 关闭整个入口和它拥有的后端。
后台启动后的日志为 `<STORY_AGENT_HOME>/logs/backend-launch.log`，入口日志为 `logs/gateway.log`。

登录自动启动不再需要时，删除上述当前用户的 plist（下次登录不启动）；当前已运行入口不会因此被结束。
入口自身代码更新需要重新启动入口或下次登录加载；普通“更新并重启”只重启 API 和 worker。

## 技术与兼容

- 入口只绑定 127.0.0.1/localhost；API 原认证、cookie、上传和 SSE 原样透传。
- 启动/退出/登录设置必须匹配 Host、Origin 和随机启动 token；退出和安装还经过 API 管理员校验。
- 不接受来自网页的 argv、目录或文件路径，不按端口查杀其它服务。
- 原 `storyagent serve` 命令不变；需直接暴露 LAN API 时使用原直连方式或 `scripts/start.sh --backend-only`。
- 退出按钮不会强制杀死长任务。若后端卡死到无法验证管理员身份，查看本机日志并手动处理，入口仍保留。
- 配置错误导致主后端不能初始化时，入口仍能显示启动失败与重试。

回滚该功能时：先等待工作完成并关闭入口，再回滚源码，然后按旧版方式运行 start.sh。不要让新版入口继续调用已经回滚的监管脚本。数据结构没有变化，原有任务记录保留。
