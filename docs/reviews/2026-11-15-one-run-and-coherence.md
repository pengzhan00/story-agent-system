## 发现（按严重度；标注已修/未修）

### P0（已修）大纲写完没有任何人读，硬伤一路带进成片
- 证据：`docs/剧本与分镜质量审查_20261028.md`（反派设计了却 0 次出场、匿名磁带来源永不交代、人物凭空出现在海边、台词比画面早一镜）。代码上，`script` 阶段写完大纲直接逐场写镜头；已有的 `reviewer.script` 只能手动点，且修订只重写镜头、改不了大纲。
- 整改：`workflow/coherence.py` + `reviewer.outline`。大纲先写 `facts`（故事的固定事实，含每个秘密的答案），写完场景再列 `threads`（埋了什么、哪一场交代）。代码检查（演员表里的人一场都没出、场里出现演员表外的人、空场、埋了没交代/先交代后埋）加模型审读，有硬伤就带意见退回重写，最多 `outline_review_rounds` 次（默认 2），保留硬伤最少的一版。

### P0（已修）写第 7 场的人只知道第 6 场的一句话
- 证据：`_write_shots` 只传 `previous`（上一场的 beat）和 `next_beat`。
- 整改：每一场都带上逐场前情 `story_so_far`、此前最后几句台词 `last_lines`、固定事实 `facts`，并写明不得与之矛盾、人物不得知道没看到没听到的事、说过的不再解释。后续集还会拿到前面各集的结尾和已固定的事实（原来只有梗概）。

### P0（已修）写好的剧本没有逻辑通读
- 整改：`reviewer.logic` 在镜头卡之前按观众顺序通读（与事实/前文矛盾、秘密提前说破、同一信息说两遍、大纲要演的事镜头里没演、台词早一镜），有硬伤的场次带意见重写（每轮最多 `script_review_max_scenes` 场，`script_review_rounds` 轮，默认 4 和 1）再读一遍。结果（评分、重写了哪几场、仍未解决的问题）写进阶段摘要，网页「剧情自检」可见。

### P0（已修）没有“一次跑到成片”的运行方式
- 证据：文档和文案里有“一键做完整部”，网页上自 1dcdea4 起没有这个按钮（死键）；默认续跑只到 `specs`，素材和合成要分两次点。
- 整改：`params.full`（CLI `workflow run --full`，网页按钮）= 从当前进度一直到成片，多集时逐集进行。

### P1（已修）服务没开要等到每个镜头各失败一次才知道
- 证据：生产库 2026-11-15 项目 7：`service_unreachable` 50 + 51 + 49 条（Draw Things、ComfyUI 未启动）。
- 整改：`workflow/preflight.py` + `GET /api/projects/{id}/preflight`。开跑前检查语言模型（后端在线、模型已装）、媒体服务、命令行工具的权重、内容闸门、声音；有阻断项就拒绝（409 `not_ready`，逐条列出）。worker 在第一个素材任务前再查一次（`workflow.not_ready`）。

### P1（已修）续跑会用过期的分镜去出素材
- 证据：项目 11：`scenes`、`music` 是 stale，`shotplan`、`specs` 是 completed。运行计划在开跑前一次算定，只含 stale 的阶段；它们跑完才把下游标成 stale，于是同一次运行不会重做下游。
- 整改：续跑计划把“会被本次运行弄过期的下游阶段”一并纳入。

### P1（已修）角色没有声音，整部片只有字幕
- 证据：项目 7、11 的角色都没有声音；资产库有 218 个已授权声音没被用上；`produce` 把这些台词按 `no_voice` 跳过。
- 整改：一键运行在出素材前按性别给每个没声音的角色各配一个库里的声音（已有的 `voices.auto_assign`），摘要列出配了谁、谁没配上。
- 与同期主线改动（e2b5621：没有参考音时 CosyVoice 用合成的系统默认声音）合并后的行为：库里有声音时仍然一人配一个；库里没有时不再跳过台词，而是所有人用同一个默认声音，就绪检查会明说“听起来是一个人”（`preflight.voice_shared`）。

### P1（已修）个别素材失败就整个停住，失败清单还丢了
- 证据：`produce` 有任务失败即抛错，`compose` 不运行；失败阶段不保存摘要，页面只剩“N 个任务失败”。
- 整改：一键运行里素材阶段标为失败并保留摘要（哪些素材、什么原因），成片照剪（时间线本来就容忍缺片并给出警告）；下次一键只补做失败项再重剪。素材一个都没做出来时不剪黑屏片，直接失败。非一键运行行为不变。

### P2（已修）
- 跳过原因 `still`、`not_voiced` 没有文案，页面显示原始 key。
- `list_scripts` 会返回同一集的多行（项目 7 第 1 集有两行）：旧行会进入“场景设计”和“前情”。现在每集只取最新一行。

### P2（未修，需要你定）参考图数量和后端能力不匹配
- 证据：生产库 2026-11-15 项目 7：24 条 `invalid_input`“the HTTP API supports one reference image”。角色上传了 2 张参考图，Draw Things 的 HTTP 接口只收 1 张，人物像和关键帧全部在校验处失败。
- 现状：适配器是故意严格的（有测试）。两种改法：只取第一张并在任务记录里写明；或在就绪检查里提前报“这个模型带不了 N 张参考图”。前者可能悄悄出一张不对的图，我没有替你选。

### P2（未修）
- 季大纲（`screenwriter.season`）没有同类检查：跨集主线的洞只能在逐集大纲里被间接发现。
- API 不知道 worker 是否在运行：没开 worker 时一键运行只会一直排队，页面只有一句提示。
- 就绪检查只在开跑前和出素材前各做一次；中途服务退出仍是逐个任务失败。

### P3（未修）
- 手动重做没有参考音频的“角色声线”规格会失败（`reference voice audio not found: None`），应在提交前拦下。
- 前端单包 532 kB；`docs/HANDOFF.md` 多处过期；`uv.lock` 一直未纳管；本基线没有打 tag。

## 真实模型上的单次试跑（2026-11-15，本机 Ollama，审稿角色的模型）
| 审读 | 对象 | 耗时 | 结果 |
|---|---|---|---|
| `reviewer.outline` | 项目 7 现有剧本的大纲 | 53 秒 | 4 分；1 条严重（林汐为何恰好在海边没有交代）、3 条中等（王经理没有戏份、磁带设定前后矛盾、情感升级太快），与 10 月 28 日人工审查的结论一致；`where` 都写成了“whole” |
| `reviewer.logic` | 项目 5 的旧剧本（3896 字） | 81 秒 | 6 分；2 条严重、2 条中等，都是具体的连戏问题（同一场里人物“再次推门而入”、能写字的人下一镜被反绑、没交代过的汤突然出现、反锁门后的站位），`where` 写成 1.3.1 / 3.2.1，能定位到场 |

这次试跑还暴露了一个误报：场景没有列出场人物时（导入的剧本），代码检查会把所有角色都报成“没出场”。已改：整份大纲都没列人物时不做这项判断，角色在 beat 里被点名也算出场。

## 没验证的（所以结论是 partial）
1. 两个审读角色是模型判断，不是证明。单次输出是靠谱的，但“带意见退回重写”之后大纲是否真的变好，只做了“取硬伤最少的一版”的防护，没有实测数据。
2. 整轮耗时没有实测：按单次约 1 分钟估，每集最坏约 3 次大纲 + 3 次审读 + 若干场重写，多出十来分钟。
3. 真实模型的一键长跑没有跑过；重任务需要你点头，我没有启动。
4. 生产还在旧代码上：要“系统 → 更新并重启”后这些才生效。
