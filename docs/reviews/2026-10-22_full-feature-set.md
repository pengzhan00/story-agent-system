## 二、本次审查中发现并已修复
- **P1(已修)保险库做成指向加密卷的软链接时,文件接口会返回 404。** 运维手册推荐的做法是 `ln -s /Volumes/X/vault $HOME/vault`,而 `GET /api/assets/{id}/file`、`/api/library/{id}/file` 用 `resolve()` 后判断"是否在数据目录内",软链接解析后落在卷上,被误判越界。修复:`util.home_file()` 按名字判断(拒绝 `..` 和绝对路径),允许跟随软链接;增加测试(软链接保险库可读;`../x`、`/etc/hosts` 仍 404)。
- **P2(已修)只读账号(viewer)无法解锁自己能看的受限内容。** 解锁是 POST,需要 write 权限。`/api/content/unlock` 加入 `signed_in_prefixes`(仍要求密码和成年确认,每次审计),viewer 只给自己解锁;增加测试。
- 一个测试写死了迁移版本 16,改为 17。

## 三、发现(按严重程度)
**P1 — 阻碍把它称作"可交付基线"**
1. 区域:实机验证。证据:上面"未能运行"。影响:新增的剪辑语法(叠化/J-L 切/多段配乐)、平台交付、条纹闪烁检测都没在真实素材上看过效果。建议:用一集真实成片(试播集)各跑一次,听看后再定默认值;阈值标定后再把 flicker/banding 从 advisory 升级。
2. 区域:受限内容 — 加密。证据:`encryption = "app"` 未实现。影响:数据库里的提示词、作业输入、素材来源不加密;只有"用户自己挂载的加密卷"一种保密方式。建议:需要时再决定是否引入 `cryptography` 依赖与密钥来源(钥匙串/环境变量),这是需要用户拍板的事。

**P2 — 应尽快处理**
3. 区域:平台交付。证据:`POST .../delivery` 在请求里同步转码(可能几分钟)并在请求里调用语言模型翻译字幕。影响:长片会让 HTTP 请求很久,浏览器超时。建议:改成后台作业(进队列、有进度),与现有"成片合成"一致。
4. 区域:受限内容遮掩范围。证据:`docs/RESTRICTED_CONTENT.md`「实现状态」:剧本/对白/分镜文字、作业进度文字不遮;受限模型用在普通项目时作业输入可见。影响:锁定状态下仍能从故事页读到文字。建议:按需要把故事库的文字接口也纳入遮掩;或明确告知用户"遮掩的是素材与提示词,不是故事文本"(文档已写)。
5. 区域:受限作业遇保险库未挂载。证据:直接 `failed_validation`,不是排队等待。影响:批量作业会整批失败,需要手动重试。建议:在 broker 里加"保险库就绪"条件,让作业保持排队并给出原因。
6. 区域:鉴权关闭时的"解锁"。证据:`auth.mode=off` 下解锁只是防误看。影响:同一台机器的其他用户可以直接读磁盘/数据库。已在文档与界面提示,真正保密靠加密卷。建议:对外/多人使用时开 token 模式并把保险库放加密卷。
7. 区域:多语字幕。证据:翻译按 40 行分块,只校验行数相同,不校验语种/质量。影响:模型偷懒返回原文也会被写入。建议:抽查(原文与译文相同的比例)并在 `delivery.json` 里记录。

**P3 — 改进**
8. 平台预设数值(响度、尺寸、帧率)是常见约定,不是任何平台的当前规范;上线前请按目标平台最新要求核对,改 `platforms.toml`。
9. 受限模型的选择器隐藏、体检按"受限"分组、分级变更时迁移文件:没做。
10. P1-2 里"用视觉模型看关键帧让视频提示词从真实姿态起步"没做。
11. 仪表盘计数与钻取:项目卡片的步骤进度、系列看板在上一轮审查已对账;本轮新增的页面没有汇总计数,无新的对账风险。
