# 自动配音与原生模型目录

基线：main@c0f7250。结论：两处定点修复已实现并完成相关验证，整体发布判定仍 partial。

## 自动配音

原问题有三个入口：工坊把参考声音设为必填；制作计划把无参考声音的台词标为 no_voice；
制作阶段再跳过这些台词。即使选择不需要用户样音的配音方式，也要求逐个角色配置声音。

现在工坊的 TTS 参考声音可选，计划与派发共享 `media/tts.py` 的能力判断。CosyVoice 无参考时
用 macOS say 自动准备通用系统样音，再交给原 CosyVoice 模型合成台词，不切换默认配音模型。
系统样音按声音、文本和格式缓存并原子写入，避免每条台词重复准备。样音、文字和来源类型
随配置/资产元数据记录；明确指定的角色声音、项目统一声音和其同意校验继续优先使用，
错误的显式音频路径不会被自动替换。可用 auto_reference=false 关闭此行为。

say 本身无需参考；其他适配器可显式声明 reference_free_tts 能力。需要参考但不支持自动声音
的模型仍会明确阻塞，不做隐式引擎降级。系统合成工具缺失时报告 missing_tool。

界面位置：项目 → 工作流程 → 统一配音声音（可选）。默认标示“自动合成通用声音（无需逐角色设置）”，
提示如何覆盖统一音色以及选择配音模型。旁白开关和“视频自带声音”选项不被本次改动改写。
声音转换仍要求源声音与目标参考；不能将 TTS 的可选参考规则直接套给声音转换。

## 原生能力目录

ACE-Step、YuE2（Phosphene）、H3.c、H3 Image 原已有注册模型和原生适配器；
工具页调用的旧接口只列 comfy/cli/http，造成已接入能力看起来缺失。

工具接口现在列出配置目录的全部模型，隐藏内部 control-tools 节点；前端同时从现有 meta 完整目录
补齐原生模型，因此旧服务进程尚未重启时也可显示它们。导入模板归属仍以工具接口为准，
新增导入结果可立即显示。列表标注“已配置”，不声称服务在线、权重存在或已通过真实任务。
新增 zh/en 原生适配器、通用连接器与使用入口说明。
